### `2.md` — Workspace Workflow (10-Step)
> I acknowledge: 10-step workflow chi tiết:
>
> 1. **Read workspace documentation** — `README.md`, `working_rule.md`, `description.md`, `architecture.md`, `api.md`, `database.md`, `workflow.md`, `coding_convention.md`, related source files
> 2. **Identify current project structure** — architecture, naming convention, coding style, existing modules, stable files
> 3. **Restate user requirement** — summary, target output, affected files, constraints
> 4. **Stop if context missing** — ask clarification questions if requirement/input-output/scope/logic/expected behavior is unclear
> 5. **Propose technical plan** — include: business requirement, feature-level interpretation, technical solution, logic/AI solution, implementation steps, risks/limitations, validation plan
> 6. **Wait for user confirmation** — DO NOT implement before approval
> 7. **Implement only approved changes** — follow existing architecture, folder structure, naming convention, coding style, service/hook/helper/module boundaries, security rules
> 8. **Do not touch unrelated stable code** — avoid broad refactoring, formatting, dependency changes, structural changes unless explicitly approved
> 9. **Validate after implementation** — check: đúng requirement? breaking changes? side effects? security risks? naming & architecture? tests/manual checks needed?
> 10. **Final report** — return: files changed, what was wrong before, why changes were made, impact, validation performed, remaining risks/side effects, completion estimate
